Research Graph City Progress Report

Project progress summary and future roadmap, July to September 2026

Executive Summary

Over the last project phase, Research Graph City moved from a visual reference idea into a working full-stack prototype. The system now ingests OpenAlex research-paper data, constructs a paper graph, transforms research clusters into a 3D city, and exposes interactive inspection tools for buildings, floors, bridges, streets, communities, papers, labels, and graph edges.

The implementation lives in a separate sibling app, ResearchGraphCity/. The original Graph_City_Web directory was used only as visual inspiration and was not modified.

Current Data

The current system supports two city modes.

City Source Current Scale Purpose
Research city OpenAlex queries: graph visualization, GraphRAG, education income mobility 1000 papers, 6457 graph edges, 13 buildings, 65 floors, 5 bridges, 12 streets, 8 communities Default broad research landscape for development and demos
Seeded city User-entered paper titles, DOIs, or OpenAlex URLs, expanded with related OpenAlex papers 991 papers, 7668 graph edges, 12 buildings, 32 floors, 7 bridges, 11 streets, 8 communities User-contextual graph city centered around supplied papers

Each paper stores available metadata such as title, DOI, OpenAlex ID, abstract text, publication year, venue, topics, keywords, authors, institutions, references, citation count, open-access status, code signal, data signal, and seed provenance when applicable.

Backend Work Completed

  • Created a FastAPI backend with typed Pydantic schemas for vertices, edges, buildings, floors, bridges, streets, communities, and summaries.
  • Implemented OpenAlex ingestion using the current https://api.openalex.org endpoint and API key support.
  • Added deduplication by DOI/OpenAlex ID and scaled the research city generation to 1000 papers.
  • Built graph edges from citation links, topic overlap, venue overlap, author/institution overlap, method/dataset overlap, text similarity, and time proximity.
  • Generated buildings from graph communities, with isolated or too-small groups preserved as outskirts instead of forcing noisy buildings.
  • Generated floors from graph core-number bands, including visible floor splits when core values are uniform.
  • Generated bridges from strong cross-building relationships and streets from weaker but nonzero research relationships.
  • Removed trivial zero-score fallback streets, so visible streets now have research relevance.
  • Added APIs for building papers, internal building edges, bridge cross edges, and city navigation.
  • Added Groq-backed structured JSON generation for summaries and city navigation, with graceful unavailable responses when the model cannot be reached.

Frontend Work Completed

  • Created a Vite, React, TypeScript, React Three Fiber frontend with Zustand state management.
  • Built a first-screen 3D city view with buildings, floors, labels, bridges, streets, grid navigation, zoom controls, and layer toggles.
  • Added clickable buildings, bridges, streets, and paper nodes with inspector panels.
  • Added building interior mode, where papers inside a building are shown as nodes organized by floor rings.
  • Added paper-title display for internal and cross-building edges so users no longer need to interpret raw IDs first.
  • Added original-label inspection for each building and paper-label inspection inside the building details.
  • Added summary-word label highlighting: selectable summary words highlight matching original labels.
  • Added selected-item visual feedback with amber rings and label outlines.
  • Added simple seeded-city input: one paper title, DOI, or OpenAlex URL per line, plus a one-click sample.
  • Added a city navigator panel where users can ask the LLM which buildings or bridges to inspect.

Visual Semantics

Visual Element Meaning
Building A cluster of related research papers.
Building footprint Mapped to paper count. Larger footprint means more papers.
Building height Mapped to graph structure and paper count through generated city layout.
Floor A band of papers inside a building, based on core-number ranges.
Base color family Broad semantic domain, such as graph/AI, health/biomedicine, economics/policy, climate/energy, education/society, or physical sciences.
Shade variation Separate communities within the same semantic domain use related but distinct color variants.
Floor shade Higher floor activation renders darker/richer; lower floor activation renders lighter.
Glow Whole-building activation from recency and citation signal.
Bridge Strong cross-building research relationship.
Street Weaker but nonzero research relationship used as navigable connective structure.
Amber outline/ring Currently selected building, bridge, street, or paper.

Metric Definitions

  • activation_score = 0.55 * recency + 0.45 * citation_signal.
  • recency = exp(-max(0, 2026 - latest_publication_year) / 5).
  • citation_signal = min(1, average_citation_count / 100).
  • profile_similarity = 0.30 J(topics) + 0.20 J(methods) + 0.15 J(datasets) + 0.10 J(venues) + 0.10 J(institutions).
  • semantic_similarity = 0.5 J(top_labels) + 0.5 J(profile topics + keywords).
  • cross_edge_strength = min(1, cross_building_edge_count / sqrt(source_node_count * target_node_count)).
  • activation_similarity = 1 - abs(source_activation - target_activation).
  • vertex_overlap is currently zero because generated buildings are disjoint paper sets.
  • llm_confidence is a reserved bridge-summary prior, currently fixed until per-bridge LLM scoring is introduced.

LLM Integration

Groq is used through an OpenAI-compatible endpoint with structured JSON output. The backend sends compact evidence packets, not the raw full graph. For city navigation, the LLM receives a compact city index containing building IDs, labels, domain metadata, metrics, bridge evidence, street evidence, and community summaries. It returns an answer, route steps, focus building IDs, focus bridge IDs, confidence, and model availability.

The live Groq-backed navigator was tested successfully with the seeded city. It returned focused building and bridge IDs for a graph neural network navigation question.

Quality And Verification

  • Backend tests currently cover ingestion normalization, edge formulas, building/floor generation, bridge thresholds, streets, communities, seeded city behavior, and LLM JSON parsing.
  • Frontend tests currently cover city loading, layer toggles, seeded-city input, paper and edge inspection, interior mode, color mapping, selected-state rendering, and city navigation UI.
  • Latest verification: 40 backend tests passed, 32 frontend tests passed, and the frontend production build passed.

Key Design Decisions

  • Keep paper nodes out of the main city view; paper-level detail appears in building interior and inspector views.
  • Use color for semantic meaning, not random decoration.
  • Use activation for glow and floor shade, not for changing the domain identity of a building.
  • Use bridges only for stronger relationships and streets only for weaker nonzero research relationships.
  • Expose original evidence wherever possible so users can audit why the city looks the way it does.

What Could Be Done Next

Data And Graph Quality

  • Move from TF-IDF text similarity to stronger embeddings for abstracts, titles, and topics.
  • Add citation direction views so users can see influence flow, not just undirected similarity.
  • Add better seed expansion using citations, references, concepts, authors, and venues rather than only title/topic searches.
  • Cache OpenAlex responses with run metadata so city generation is reproducible.

Community And Layout

  • Use hierarchical communities: districts, neighborhoods, buildings, floors, and papers.
  • Separate semantic domains from graph communities in the UI so users can switch between domain-color and modularity-color views.
  • Add a street-layout optimization step inspired more directly by the original Graph City algorithm, with cleaner routing and fewer visual crossings.
  • Expose outskirts or small isolated clusters as parks, markers, or small structures instead of hiding them.

User Workflows

  • Add paper search and filters by year, venue, author, topic, citation count, and seed status.
  • Add saved tours generated by the city navigator, where users can step through buildings and bridges in order.
  • Add exportable evidence reports for selected buildings, bridges, or whole seeded cities.
  • Add a compact seed review stage that shows the 10 user seeds as a regular graph before expanding to the 1000-paper city.

LLM And Evaluation

  • Add retrieval over papers for deeper building-specific questions after the user enters a building.
  • Add confidence calibration based on available evidence instead of a fixed prior.
  • Add hallucination checks that reject route targets not present in the city index.
  • Add evaluator tests for navigation quality on known seed sets.

Production Readiness

  • Add background jobs for seeded-city builds so large OpenAlex requests do not block the API request lifecycle.
  • Add persistent storage for multiple user-generated seeded cities.
  • Add deployment configuration, monitoring, and rate-limit handling.
  • Split frontend bundles with dynamic imports for Three.js-heavy views.

Conclusion

Research Graph City now demonstrates the core idea: a research-paper graph can be transformed into a navigable 3D city with meaningful buildings, floors, bridges, streets, colors, labels, and LLM-guided inspection. The next phase should focus on deeper retrieval, stronger graph semantics, cleaner spatial layout, and user workflows for building and comparing multiple seeded cities.
